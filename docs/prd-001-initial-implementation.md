# PRD-001：眸润（Moirun）初始功能实现

## 问题陈述

长时间伏案工作者往往因专注而忽略饮水与眼部休息，导致身体亚健康。现有工具多为浏览器插件或手机应用，无法在桌面工作流中形成有效阻断。用户需要一款真正驻留于系统层面、按个人节奏提醒、不打扰但关键时刻能强制暂停工作的跨平台桌面应用。

## 解决方案

眸润（Moirun）是一款以系统托盘静默驻留的跨平台（macOS + Windows）桌面应用，通过两套差异化的提醒策略，分别处理"温和建议"（喝水）与"必要阻断"（护眼）两类健康需求。所有配置持久化，统计数据跨日自动重置，勿扰模式灵活覆盖会议等场景。

## 用户故事

1. 作为长时间使用电脑的职场人士，我希望应用常驻系统托盘不占用桌面空间，以便它默默守护而不干扰我的工作流。
2. 作为需要定时补水的用户，我希望每30分钟收到一次轻量喝水提醒，以便养成规律饮水习惯。
3. 作为希望自由控制提醒的用户，我希望可以单独关闭喝水提醒，以便在不需要时减少打扰。
4. 作为收到喝水提醒的用户，我希望点击"已喝水"后计时器立即重置，以便下一次提醒从这一刻重新开始。
5. 作为需要保护视力的用户，我希望每30分钟收到一次护眼弹窗提醒，以便强制自己离开屏幕休息。
6. 作为护眼弹窗弹出时的用户，我希望看到倒计时提示剩余休息时间，以便心里有数、安心等待。
7. 作为暂时无法休息的用户，我希望可以延后护眼提醒5或10分钟，以便完成当前紧要事务后再休息。
8. 作为偏好自由的用户，我希望护眼提醒处于"温和模式"，弹窗随时可关闭，以便保持完全自主。
9. 作为需要一定约束的用户，我希望护眼提醒处于"锁时模式"，倒计时结束前无法关闭弹窗，以便真正停下来休息。
10. 作为需要强约束的用户，我希望护眼提醒处于"严格模式"，所有显示器均被全屏遮罩覆盖且倒计时结束前不可操作，以便彻底阻断工作流。
11. 作为正在开会或演示的用户，我希望一键开启"勿扰模式"暂停所有提醒，并可选择30分钟后、1小时后或手动恢复，以免尴尬。
12. 作为关心健康的用户，我希望查看今日饮水次数和护眼休息次数的统计，以便量化自己的健康行为。
13. 作为跨日使用电脑的用户，我希望统计数据在日期变更时自动清零，以便每日重新计数。
14. 作为希望开机即用的用户，我希望可选配置"开机自启"（默认关闭），以便无需每次手动启动。
15. 作为多显示器用户，我希望严格模式的护眼提醒覆盖我所有连接的显示器，以便无法通过切换屏幕逃避休息。
16. 作为偏好自定义的用户，我希望在设置窗口中调整喝水间隔和护眼间隔，以便适配个人工作节奏。

## 实现决策

### 模块划分

| 模块 | 层级 | 职责 |
|------|------|------|
| `TimerEngine` | Rust | 管理喝水与护眼两个独立计时器；处理计时器重置（喝水确认）、延后（护眼延后）、勿扰暂停/恢复；跨日检测触发统计重置 |
| `TrayManager` | Rust | 构建系统托盘图标与菜单；菜单项包含：喝水开关、护眼开关、勿扰模式（子菜单：30分钟/1小时/恢复）、今日统计、打开设置、退出 |
| `WindowManager` | Rust | 管理三类窗口：设置窗口（可调整大小）、护眼弹窗（固定尺寸居中）、严格模式遮罩窗口（全屏无装饰，多实例对应多显示器） |
| `StatsStore` | Rust | 基于 `tauri-plugin-store` 读写键值配置与统计数据；封装跨日检测逻辑；暴露命令给前端查询 |
| `NotificationService` | Rust | 封装 `tauri-plugin-notification`，发送喝水提醒的系统原生通知 |
| `SettingsPage` | React | 设置窗口前端页面：喝水提醒开关与间隔、护眼提醒开关与间隔、护眼强度三选一、开机自启开关 |
| `EyeCarePopup` | React | 护眼弹窗前端页面：显示剩余倒计时、延后按钮（5分钟/10分钟）、严格模式下的全屏遮罩渲染 |
| `StatsMiniView` | React | 设置页内嵌或独立小窗展示今日饮水次数与护眼休息次数 |

### 关键接口与数据流

- **Rust 命令集**：前端通过 `invoke` 调用 Rust 命令，涵盖：
  - `get_settings` / `set_settings` — 读写配置
  - `get_today_stats` — 获取今日统计
  - `confirm_water` — 用户点击"已喝水"，通知 Rust 重置喝水计时器
  - `snooze_eye_care(minutes)` — 延后护眼提醒
  - `toggle_do_not_disturb(duration)` — 开启/关闭勿扰
  - `open_settings_window` / `open_eye_care_window` / `close_all_overlays` — 窗口管理

- **Rust 到前端事件**：通过 `emit` 推送事件，涵盖：
  - `water-reminder` — 触发喝水系统通知
  - `eye-care-reminder` — 触发护眼弹窗显示
  - `stats-updated` — 统计变更时推送最新数据
  - `do-not-disturb-changed` — 勿扰状态变更

- **配置 Schema**（持久化于 `plugin-store`）：
  ```json
  {
    "water_reminder_enabled": true,
    "water_interval_minutes": 30,
    "eye_care_enabled": true,
    "eye_care_interval_minutes": 30,
    "eye_care_intensity": "gentle" | "locked" | "strict",
    "eye_care_lock_seconds": 20,
    "auto_start": false
  }
  ```

- **统计 Schema**（持久化于 `plugin-store`，跨日重置）：
  ```json
  {
    "date": "2026-05-16",
    "water_count": 0,
    "eye_care_count": 0
  }
  ```

### 架构决策

- **计时器位于 Rust 侧**：前端不持有计时器，Rust 进程在后台持续运行，即使前端窗口全部关闭（托盘驻留场景）也能正常触发提醒。
- **喝水提醒使用系统原生通知**：遵循 ADR-0002 的双策略设计，通过 `tauri-plugin-notification` 发送 Toast，点击通知的"已喝水"按钮调用 Rust 命令重置计时器。
- **护眼弹窗为独立 Tauri 窗口**：区别于主窗口，护眼弹窗为无边框或精简边框的小窗口，严格模式额外创建全屏遮罩窗口。
- **严格模式多显示器覆盖**：遵循 ADR-0003，Rust 侧枚举所有可用显示器，为每个显示器创建一个全屏半透明遮罩窗口，护眼弹窗居中于当前活动显示器。
- **勿扰模式由 Rust 计时器管理**：开启勿扰时暂停所有提醒计时器，设置恢复时间后自动恢复，或用户手动恢复。
- **跨日检测由 Rust 侧定时执行**：每5分钟检查一次存储的日期键，发现变更时重置统计计数。

### 权限与安全

- `capabilities/default.json` 需追加：`store:default`、`notification:default`、`autostart:default`。
- 严格模式遮罩窗口需 `core:window:allow-set-focus`、`core:window:allow-set-size` 等窗口管理权限。

## 测试决策

- **Rust 模块单元测试**：`TimerEngine` 的计时逻辑、延后逻辑、勿扰状态机为纯逻辑，可脱离 Tauri 运行时以标准 Rust 测试覆盖；使用 `std::time::Instant` 的抽象或 mock 时间推进来避免真实等待。
- **配置读写集成测试**：验证 `StatsStore` 与 `plugin-store` 的读写一致性，以及跨日重置逻辑。
- **前端组件测试**：`SettingsPage` 的表单交互、`EyeCarePopup` 的倒计时渲染使用 React Testing Library，仅测外部行为（按钮点击后调用正确的 invoke），不测内部状态。
- **端到端测试暂不纳入**：Tauri 的端到端测试需额外工具链，首版以手工验证为主。

## 范围之外

- 用户账户与云端同步
- 历史数据统计与趋势图表
- 自定义音效与语音播报
- 番茄工作钟或其他非健康提醒功能
- 移动端（iOS/Android）适配
- 多语言国际化
- 插件扩展机制

## 补充说明

- 护眼弹窗的倒计时锁时长暂定为20秒，可在设置中调整（范围10-60秒）。
- 开机自启依赖 `tauri-plugin-autostart`，用户首次开启时操作系统可能弹出权限提示。
- 托盘图标需提供明暗两套适配（macOS 菜单栏深色/浅色模式）。
- 严格模式在多显示器场景下的窗口对齐，以 Tauri 2.x 的 `Monitor` API 获取各显示器尺寸与坐标进行计算。
